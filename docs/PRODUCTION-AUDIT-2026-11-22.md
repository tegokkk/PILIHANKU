# Audit kesiapan production PILIHANKU

Tanggal: 22 November 2026 (Asia/Bangkok). Lingkungan: Windows, Node 24.21.0, PostgreSQL lokal sungguhan, Chromium in-app. **Keputusan: belum siap production.** Perbaikan kode lokal tidak menggantikan verifikasi hosting, pemulihan cadangan, materi BK, persetujuan sekolah, atau uji aksesibilitas pada perangkat sasaran. Pengukuran beban kali ini juga belum memenuhi target p95.

> Tindak lanjut permintaan perbaikan error 500, 22 November 2026: database development lokal `127.0.0.1/pilihanku` masih hanya memiliki migration 001–004. Migration 005 kemudian diterapkan pada target development yang telah diverifikasi, tanpa mengubah jumlah baris users, schools, classes, student_profiles, student_registrations, exploration, consultations, atau cards. `/api/health`, `/api/auth/me`, dan `/api/auth/csrf` kembali 200 melalui server/proxy lokal. Beranda dan halaman Masuk diperiksa ulang di browser; console error/warning kosong. Pernyataan database pengguna belum dimigrasikan di bagian audit berikut merupakan kondisi saat audit awal, sebelum tindak lanjut ini. Tidak ada migration production atau deployment.

## Cakupan dan perlindungan pekerjaan

Audit membaca README, dokumen akses/verifikasi, struktur aplikasi, konfigurasi runtime/container/proxy, seluruh modul API, migration/job, delapan halaman utama, context, request, navigasi, penyimpanan, ekspor, dan pengujian. Tidak ditemukan AGENTS.md yang berlaku. Folder kerja tidak memiliki metadata Git; riwayat commit dan kebocoran pada riwayat repository tidak dapat diperiksa.

Sumber sebelum perubahan disalin ke `backend/.local/audit-before-20261122/`, tanpa `.env`. Daftar perubahan dan checksum disimpan di `output/qa/production-audit/changed-files.json`. Referensi HTML Stitch tidak diubah. Tidak menambah dependensi atau mengubah lockfile. Kredensial yang sudah ada tidak dicetak atau dirotasi. Tidak melakukan deployment, bootstrap, seed, migration, retensi, atau penghapusan pada database aplikasi yang sudah ada.

Pengujian memakai database baru `pilihanku_audit_20261122_test`; browser memakai database berbeda `pilihanku_browser_audit_20261122_test`, berisi akun/sekolah/pesan sintetis. Port audit 3102 terpisah dari server pengguna. Perubahan sesi untuk uji kedaluwarsa dibatasi pada akun sintetis di database browser tersebut. URL koneksi dan rahasia tidak dimasukkan ke laporan/bukti publik.

### Alur browser → API → database → tampilan

1. Beranda terbuka sebelum login. Akun pending gagal login; pemeriksaan status dengan kredensial tetap tersedia. Pendaftaran sintetis melalui UI menghasilkan pending, superadmin menyetujui, lalu siswa yang sama berhasil login. SQL menunjukkan user/pengajuan approved dan tepat satu profil.
2. Dua puluh empat respons Suka menampilkan enam skor 12 dengan penjelasan seri; tidak memilih jurusan otomatis. Tiga tugas disimpan, reload memulihkan ketiganya. SQL menunjukkan 24 jawaban dan tiga tugas pada revision 27 pada saat pemeriksaan.
3. Konsultasi hanya memilih Rencana. BK melihat Rencana Dibagikan, tiga bagian lain Tidak dibagikan. BK meninjau lalu menjadwalkan 1 Desember 2026, pukul 10.00 Asia/Jakarta, tempat sintetis. Siswa melihat tanggal/jam/zona/tempat yang sama. SQL hanya memuat kunci berbagi `plan`.
4. Restart server audit sempat membuat simpan jadwal gagal jaringan. Isian tetap tersedia; retry berhasil dan tidak menghasilkan sukses palsu. Secara terpisah, request eksplorasi ditahan dengan CDP: kontrol Langkah baru tidak dirender. Request digagalkan, UI memberi Muat ulang data akun; retry memulihkan tiga tugas.
5. Unduh PDF benar-benar menghasilkan file pada `output/qa/production-audit/browser-plan.pdf`. Uji PDF panjang otomatis lulus; PDF unduhan browser kali ini tidak dirender ulang dengan Poppler, sehingga tidak diklaim sudah ditinjau visual per halaman.
6. Dua tab diuji logout dan pergantian akun. Sesi siswa sintetis dibuat melewati idle di database test; reload dan tombol kembali berakhir di Masuk, dengan nol tombol kirim privat.
7. Beranda, pendaftaran, empat halaman siswa, detail dashboard BK, dashboard dan kelola superadmin, serta kelola BK diperiksa pada lebar CSS 360, 390, 768, 1024, 1440. Tidak ada overflow horizontal halaman pada state yang diukur. Stepper/tabel boleh mempunyai area gulir lokal. Sebagian data mentah tersedia di `browser-layout.json`; pengukuran awal sebelum reset runtime browser dicatat di hasil tool, bukan direka ulang ke JSON.
8. Menu keyboard: fokus awal, Shift+Tab, Escape, dan pengembalian fokus diperiksa. Console error/warning pada pemeriksaan akhir halaman konsultasi kosong. Ini tidak mencakup setiap browser/state/alat bantu. Interception dan override viewport sementara telah dibersihkan.

## Inspeksi keamanan dan integritas yang dipertahankan

Identitas/role/status berasal dari sesi dan baris pengguna di server; payload strict, query berparameter, Argon2id, CSRF + Origin, version sesi, batas idle/absolut, owner konsultasi, penugasan BK, scope sekolah, suppression agregat, optimistic revision, snapshot persetujuan, cascade penghapusan, dan ledger tetap dipertahankan. Konten string ditampilkan sebagai teks React; tautan terbit wajib HTTPS dan memakai noopener/noreferrer. Tidak ada jalur Mode Tamu, impor draf lama, role dari localStorage, atau akses superadmin rutin ke refleksi privat yang diaktifkan kembali.

Service worker hanya menggunakan cache shell/aset publik; private API melewati cache. Source map tidak diaktifkan pada konfigurasi build. `.dockerignore` mengecualikan `.env`, `.local`, output QA, dan dependensi host. Ini kesimpulan inspeksi dan pengujian yang disebutkan, bukan sertifikasi bahwa semua serangan atau seluruh riwayat sumber bebas masalah.

Advisori primer yang diperiksa: [rilis keamanan Express Oktober 2026](https://expressjs.com/en/blog/2026-10-31-security-releases/) menyebut perbaikan body-parser 2.4.0; lockfile proyek sudah memakai 2.4.0. [React Router GHSA-rxv8-25v2-qmq8](https://github.com/remix-run/react-router/security/advisories/GHSA-rxv8-25v2-qmq8) diperbaiki pada >=7.14.0; versi proyek 7.18.6 dan menggunakan BrowserRouter. [Advisori resmi jsPDF](https://github.com/parallax/jsPDF/security/advisories) juga diperiksa. Kontrak store mengacu pada [dokumentasi express-rate-limit](https://github.com/express-rate-limit/express-rate-limit/blob/main/docs/guides/creating-a-store.mdx). Hasil npm audit bukan bukti keamanan menyeluruh.

## Urutan penerapan dan rollback yang dapat ditinjau

1. Tinjau manifest/perubahan lokal dan backup sumber. Belum ada commit/PR karena folder bukan checkout Git.
2. Pada target yang diotorisasi, cadangkan database dan ledger secara terpisah. Migration `005_rate_limits.js` bersifat menambah tabel/index, tanpa mengubah data domain. **Jalankan migration sebelum menjalankan kode baru**, termasuk untuk server development yang memakai versi ini. Database pengguna sengaja belum dimigrasikan dalam audit.
3. Build, siapkan environment production yang benar, hapus variabel bootstrap dari environment proses server, dan gunakan database production tanpa sekolah demo. Guard menolak startup bila syarat itu tidak terpenuhi. Jangan menjalankan fixture audit atau seed demo pada production.
4. Smoke test role/status/CSRF/kepemilikan sampai database, aktifkan retensi berkala dan alert kegagalannya, verifikasi backup/restore, baru buka trafik setelah seluruh penghalang rilis ditutup dan deployment diotorisasi.
5. Jika rollback aplikasi diperlukan, kode lama dapat berjalan dengan tabel rate_limit_buckets tambahan tetap ada. Tidak perlu menghapus tabel atau memundurkan data domain. Restore database hanya melalui runbook ledger/retensi; jangan membuka trafik sebelum penghapusan diterapkan kembali.

Perubahan lokal siap ditinjau. **Proyek belum dinyatakan siap production**, terutama karena target performa, bukti pemulihan/infrastruktur, validasi materi, dan pemeriksaan perangkat sasaran masih terbuka.
